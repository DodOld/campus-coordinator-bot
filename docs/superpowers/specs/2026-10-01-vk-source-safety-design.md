# Безопасная первичная настройка VK-источников

## Цель

Не публиковать в Telegram записи, которые не принадлежат отслеживаемому VK-сообществу, и не отправлять историю публикаций при первом добавлении источника.

## Поведение мониторинга

- После `wall.get` мониторинг принимает запись только тогда, когда её `from_id` совпадает с `owner_id` источника. Это отсекает рекламные и иные сторонние записи, которые VK API может включить в стену сообщества.
- Ссылка на оригинал строится по фактическому владельцу записи, а не предполагаемому ID источника.
- При `!vk add` бот получает текущие записи сообщества, отбирает собственные и отмечает их как обработанные в той же транзакции, что и создание источника. Уведомления не отправляются. Последующие запуски публикуют только новые собственные записи.
- Уже созданные источники сохраняют обычный режим работы; существующая дедупликация по `(source_id, post_id)` не меняется.

## Команды и документация

- В Debug-теме действует `!help` для любого участника разрешённой группы. Сообщение показывает `!all`, `!vk list` и справку по `!vk add`/`!vk remove`; последние две операции требуют прав администратора.
- README полностью написан по-русски и описывает ограничения первого сканирования VK, `!help`, темы и безопасную настройку.

## Ошибки и проверки

- Ошибки VK API при первичной инициализации не создают частичный источник и сообщаются только в Debug без секретов.
- Тесты покрывают фильтрацию чужого автора, отсутствие публикаций истории при добавлении и доступность `!help` не-администратору в Debug.
