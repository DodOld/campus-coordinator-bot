# Временная интеграция расписания 0B62

## Границы

Текущий Go-источник считается настроенным на группу 0B62. Настройка произвольной группы не входит в эту версию: формат преобразования публичного ID ТПУ в источник ICS пока не подтверждён.

## Команды

Команда доступна только в Debug-теме разрешённой группы и молча игнорируется в личных чатах, неразрешённых группах и других темах.

- `!schedule` — расписание на сегодня.
- `!schedule mon`, `tue`, `wed`, `thu`, `fri`, `sat` — ближайший соответствующий день недели.
- `sun` намеренно не принимается; команда выводит безопасную подсказку в Debug.

`!help` содержит эту таблицу и указывает ограничение на Debug.

## Выполнение и публикация

- Go-бинарник получает дату через аргумент `--date YYYY-MM-DD`, отвечает строго JSON и не содержит в выводе диагностический stderr.
- Python сохраняет `ScheduleProvider` и `ICalendarScheduleProvider`, добавляя отдельный адаптер для Go-процесса с ограничением времени и проверкой JSON.
- Команда показывает в Debug статус запуска, а готовое расписание публикует только в Schedule. При ошибке деталь остаётся в Debug, а Schedule не получает техническую информацию.
- Ежедневная задача запускается в 00:00 по Томску (UTC+7) и публикует расписание на текущую дату в Schedule; повторный запуск за те же сутки не создаёт дубликат.

## Сборка и данные

- Go собирается multi-stage в Docker под целевую платформу контейнера; `GO_SCHEDULE_BINARY` по умолчанию указывает на `/usr/local/bin/schedule-bot`.
- В Git остаются Go-исходники и зависимости. Собранный бинарник, загруженные `.ics` и локальные данные исключаются.
- README описывает переменную окружения, команды, время Томска (UTC+7), получение публикаций и временную привязку к 0B62.

## Проверки

Тесты покрывают разбор разрешённых дней, доступ только из Debug, запуск Go с датой, ошибки/таймаут/невалидный JSON, идемпотентность ежедневной публикации и ограничение длины Telegram-сообщения.
